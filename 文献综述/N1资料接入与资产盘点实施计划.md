# N1 资料接入与资产盘点实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全量盘点 Notion“AGV库2”和 GitHub `paper` 文献资产，建立逐条可复核的 Notion—GitHub 对应关系，并交付资产清单、对应表及重复与缺失报告。

**Architecture:** Notion 数据库是结构化分析来源，`paper` 根目录和 `原始论文/` 是原文证据来源。匹配采用规范化标题、作者线索和必要的原文核查分级，不修改任何原始文献；三份永久成果与仪表盘保存在 `文献综述/`，中间数据只保存在本地临时目录。

**Tech Stack:** Notion 只读查询、PowerShell、Git、Markdown、SHA-256。

**Spec:** `文献综述/九节点研究控制台设计.md`

## Global Constraints

- 不读取或写入 `paper-explaination`。
- 不修改、移动、重命名或删除原始文献。
- 未核验的匹配必须标记为“待确认”，不得强行配对。
- 永久成果提交 Git；过程日志不提交，用户查看确认后删除。
- N1 只判断资产和对应关系，不提前形成算法或研究结论。
- 每条 Notion 记录最终必须是“已匹配”“缺原文”或“待确认”之一。

### Task 2: 建立逐条 Notion—GitHub 对应关系

**Files:**

- Create: `文献综述/00_资产与证据/Notion-GitHub对照表.md`
- Read: `*.md`
- Read: `原始论文/*.md`

**Interfaces:**

- Consumes: Task 1 的全量 Notion 行和 GitHub 文献文件清单。
- Produces: 每条 Notion 记录唯一一行的匹配表，状态限定为“已匹配”“缺原文”“待确认”。

- [ ] **Step 1: 生成规范化标题候选**

对 Notion“论文名称”和 GitHub 文件名执行可审计的机械规范化：移除 `MinerU_markdown_` 前缀、导出数字后缀、文件扩展名、明显的作者尾缀与不影响识别的空白；保留原始值供复核。

- [ ] **Step 2: 执行精确和高置信匹配**

标题规范化后完全相同，或标题主体相同且作者线索一致，标为“已匹配”；记录仓库相对路径和匹配依据。

- [ ] **Step 3: 核查模糊候选**

对缩写、译名、截断标题及 L025/L026/L031 等编号文件读取标题页或正文元数据。不能获得唯一证据时标为“待确认”，列出候选路径，禁止取最高相似度后自动通过。

- [ ] **Step 4: 标记缺原文和孤立原文**

Notion 无任何合理候选的记录标为“缺原文”；GitHub 有原文但没有 Notion 记录的文件列入“GitHub 孤立文献”，但不伪造 Notion 行。

- [ ] **Step 5: 写入全量对照表**

固定列为：序号、Notion 论文名称、Notion 页面、GitHub 文件、状态、匹配依据、备注。表后附已匹配、缺原文、待确认和 GitHub 孤立文献的数量汇总。

- [ ] **Step 6: 验证逐条覆盖**

验证对照表中的 Notion 数据行数等于数据库总数；每行恰有一个合法状态；已匹配路径均真实存在；同一路径被多条 Notion 记录引用时必须进入重复审查。

- [ ] **Step 7: 提交 Task 2**

```powershell
git add -- '文献综述/00_资产与证据/Notion-GitHub对照表.md'
git commit -m "Map Notion records to literature sources"
```

### Task 3: 审计重复、缺失和版本关系

**Files:**

- Create: `文献综述/00_资产与证据/重复与缺失报告.md`
- Read: `文献综述/00_资产与证据/Notion-GitHub对照表.md`

**Interfaces:**

- Consumes: GitHub 文件清单、SHA-256、文件大小、规范化标题和 Task 2 对照表。
- Produces: 完全重复、疑似重复、缺失、孤立和版本关系的分类报告。

- [ ] **Step 1: 计算受检原文 SHA-256**

对研究对象原文和相关论文正文计算 SHA-256；哈希相同者标为“字节级完全重复”，不得仅凭相似文件名删除任何文件。

- [ ] **Step 2: 检查标题级疑似重复**

对规范化标题相同但哈希不同的文件记录为“疑似版本关系”，核查作者、年份和正文标题，不自动合并。

- [ ] **Step 3: 汇总缺失和孤立项**

从 Task 2 汇总 Notion 缺原文、待确认、GitHub 孤立文献和一对多/多对一关系。

- [ ] **Step 4: 写入重复与缺失报告**

报告每个问题的证据、影响和建议动作；N1 只提出建议，不执行删除、移动、重命名或 Notion 更新。

- [ ] **Step 5: 验证报告覆盖**

报告中的数量必须与对照表汇总一致；每个 SHA-256 重复组和每个歧义组均列出所有相关路径。

- [ ] **Step 6: 提交 Task 3**

```powershell
git add -- '文献综述/00_资产与证据/重复与缺失报告.md'
git commit -m "Report N1 literature gaps and duplicates"
```
