# N3 研究问题与范围冻结实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基于 N1–N2 已验收语料和证据，建立 AGV 智能调度问题树，冻结 2～3 个可由文献回答的研究问题、研究边界和术语。

**Architecture:** 先从 29 篇书目和 24 条证据记录提取问题对象、决策、动态事件和评价维度，形成问题树与候选 RQ；再用证据覆盖和 FINER 评分筛选；经用户确认后冻结 RQ、边界和术语。N3 只确定“问什么”，不提前完成 N4 分类、N5 机制综合或 N8 创新结论。

**Tech Stack:** Markdown、PowerShell、Git、N1/N2 永久成果、Notion 只读证据。

**Spec:** `文献综述/九节点研究控制台设计.md`

## Global Constraints

- 不修改、移动、重命名或删除任何原始文献。
- 不读取或写入 `paper-explaination`。
- 仅使用 N2 允许正式使用的证据；`部分支持`必须携带限定，分析推断不得冒充作者结论。
- RQ 必须可由现有语料或明确的补充检索回答，不以“AGV 智能调度”这样的宽泛主题充当研究问题。
- 问题分类主轴采用：应用场景、决策对象、环境、扰动、方法族、评价目标；机器—AGV耦合方式作为附加轴。
- 用户确认范围与分类轴后才写入“冻结”；确认前状态保持“候选框架”。

## N3 完成定义

- 形成可追溯的问题树。
- 冻结 2～3 个单句、可回答的 RQ，并通过 FINER 门槛。
- 每个 RQ 明确纳入证据、排除证据和预期回答形式。
- 研究边界说明和术语表完整，后续 N4–N9 使用同一口径。
- 永久成果、仪表盘和 Git 记录进入 `main`；原始文献无改动。
