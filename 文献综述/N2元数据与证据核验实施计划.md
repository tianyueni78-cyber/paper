# N2 元数据与证据核验实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 N1 确认的 29 篇文献建立可追溯书目记录，核验 24 条 Notion 分析字段与原文的一致性，并输出可用于后续节点的证据状态和人工确认项。

**Architecture:** GitHub 原文转换文本提供原文证据，Notion“AGV库2”提供待审分析字段，DOI、期刊/出版社页面、Crossref、OpenAlex 等权威来源提供书目存在性核验。书目核验与内容证据核验分别判定；无法确认的字段保留并标记，不进入正式结论集。

**Tech Stack:** Markdown、PowerShell、Notion 只读查询、Crossref/OpenAlex/Semantic Scholar 或 DOI 官方解析、Git。

**Spec:** `文献综述/九节点研究控制台设计.md`

## Global Constraints

- 不修改、移动、重命名或删除任何原始文献。
- 不读取或写入 `paper-explaination`。
- 不回写 Notion；是否补充缺失记录或字段由用户另行批准。
- 书目存在性、来源质量与结论证据分别判定，不能互相替代。
- 正文中的作者主张、跨文推断和研究建议必须分开标记。
- 无法核实的字段标为“未核验”或“需人工确认”，不得猜测补齐。
- 外部检索优先使用 DOI、期刊、出版社或权威书目数据库，并记录访问日期和查询依据。
- N2 不提前执行 N3 的研究问题冻结或 N4–N8 的综合判断。

## 统一状态词汇

### 书目核验状态

| 状态 | 定义 |
|---|---|
| 已核验 | 原文题名页与 DOI/期刊/出版社或权威书目记录一致 |
| 原文核验 | 原文可定位，但当前没有独立权威元数据或 DOI |
| 部分核验 | 部分字段获得确认，仍有明确缺口或冲突 |
| 待人工确认 | 自动核验无法唯一解决冲突 |

### Notion 字段证据状态

| 状态 | 定义 |
|---|---|
| 直接支持 | 原文有明确陈述或表格，可定位到章节与检索锚点 |
| 部分支持 | 原文支持核心意思，但 Notion 表述扩大、压缩或混合了多个条件 |
| 分析推断 | 表述是基于原文的合理分析，不是作者直接结论 |
| 未定位 | 在当前原文转换文本中找不到充分证据 |
| 不适用 | 该字段对综述、无实验论文或对应研究不适用 |

### Task 2: 提取并核验 29 篇书目元数据

**Files:**

- Modify: `文献综述/00_资产与证据/N2_书目核验表.md`
- Read: 29 篇原文转换文本

**Interfaces:**

- Consumes: Task 1 书目骨架和原文。
- Produces: 29 篇文献的题名、作者、年份、来源、DOI及逐条核验状态。

- [ ] **Step 1: 从原文提取书目字段**

对每篇检索标题、作者、单位、摘要前信息、引用格式、DOI、期刊/学位授予单位和年份；记录可复查的章节或文本锚点。文件名只作候选，不作最终证据。

- [ ] **Step 2: 先按显式 DOI 核验**

对原文中存在 DOI 的条目解析 DOI，并核对题名、作者、年份和来源。DOI 可解析但题名不匹配时标记冲突，不得判为“已核验”。

采用 Crossref、OpenAlex 或期刊/学位论文权威页面进行精确标题查询。每篇记录查询来源、访问日期、返回标识和匹配依据；API 失败必须显式记录为降级。

- [ ] **Step 4: 处理中文学位论文与内部编号文件**

中文学位论文若外部数据库无结果，以原文封面/题名页作“原文核验”；L025、L026、L031 必须以正文正式题名替代内部文件名说明。

- [ ] **Step 5: 执行逐行完整性检查**

每行至少有正式题名、作者或责任者、年份、来源、原文定位、核验状态；缺项必须写明原因而非留空。

- [ ] **Step 6: 提交书目核验表**


### Task 3: 核验 24 条 Notion 分析字段的原文证据

**Files:**

- Create: `文献综述/00_资产与证据/N2_引用与证据状态表.md`
- Read: `文献综述/00_资产与证据/Notion-GitHub对照表.md`
- Read: 24 篇对应原文

**Interfaces:**

- Consumes: Notion 全字段、N1 对照表和 Task 2 的书目身份。
- Produces: 每条 Notion 记录的字段级状态、原文定位和可用性结论。

- [ ] **Step 1: 全量查询 Notion 字段**

重新查询 24 条记录的场景、静/动态、扰动、核心决策、优化目标、模型、算法及其职责、关键假设、数据/算例、指标、论文结论、不足、可迁移点、可运行基线和实验方案。

- [ ] **Step 2: 分离原文字段与分析字段**

将模型、算法、数据、指标、论文结论和作者明确局限作为原文证据字段；将可迁移点、可运行基线和实验方案默认视为分析字段，除非原文直接提出相同内容。

- [ ] **Step 3: 为每条论文建立证据定位**

每条至少核验“算法及其职责、数据/算例、指标、论文结论、不足”五项；记录原文章节和可搜索短语锚点，避免只写“见原文”。其余字段标记直接支持、部分支持、分析推断、未定位或不适用。

- [ ] **Step 4: 校准 Notion 结论强度**

检查 Notion“论文结论”是否保留了论文内部实验条件。若将单案例结果写成普遍有效、把方法描述写成性能结论或把未来工作写成已证实不足，降为“部分支持”或“分析推断”。

- [ ] **Step 5: 形成正式可用性规则**

只有“直接支持”字段可不加额外说明地进入后续事实表；“部分支持”必须携带限定条件；“分析推断”必须标明为本研究分析；“未定位”不得进入正式结论。

- [ ] **Step 6: 验证覆盖与定位**

证据状态表覆盖 24/24 条 Notion 记录；每条有结论状态和至少一个原文锚点；所有状态属于固定词汇。

- [ ] **Step 7: 提交证据状态表**

```powershell
git add -- '文献综述/00_资产与证据/N2_引用与证据状态表.md'
git commit -m "Audit Notion claims against source texts"
```
