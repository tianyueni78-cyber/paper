# AGV 智能调度九节点研究控制台设计

## 1. 目标与边界

本目录用于保存面向 AGV 智能调度领域的文献综述、研究地图、方法比较、实验评价和研究决策成果。

- `paper` 仓库根目录中的文献原文保持原位，不移动、不改写。
- Notion 数据库“AGV库2”作为结构化分析来源。
- GitHub `paper` 仓库中的 Markdown 论文作为原文证据来源。
- `paper-explaination` 不属于本工作流，不读取、不写入。
- 永久研究成果保存在本目录。
- 过程日志不提交 Git；用户查看并确认后删除。
- 未核验内容必须标明状态，不得作为确定结论。

## 2. 控制台实现

采用 GitHub 原生 Markdown 控制台，不建设独立网站。控制台由一个状态页和若干永久成果文件组成。

```text
文献综述/
├─ DASHBOARD.md                 # 九节点状态、验收结论、成果入口
├─ 00_资产与证据/
├─ 01_研究问题/
├─ 02_问题情境/
├─ 03_算法机制/
├─ 04_方法体系/
├─ 05_指标与实验/
├─ 06_证据综合/
├─ 07_研究空白与决策/
├─ 08_综述报告/
└─ 九节点研究控制台设计.md
```

只在产生实际成果时创建对应子目录和文件，不预先生成空文件。

## 3. 永久研究成果清单

### 3.1 资产与证据

1. Notion—GitHub 文献对应表。
2. 文献资产清单、重复项、缺失项和版本关系。
3. 标题、作者、年份、来源、DOI 等书目信息核验表。
4. 结论—原文证据定位表及未核验事项清单。

### 3.2 研究问题与问题情境

5. AGV 智能调度问题树与术语表。
6. 两至三个可回答的研究问题及范围说明。
7. 应用场景、资源结构、静动态、扰动和约束分类体系。
8. 问题情境—核心决策矩阵及覆盖热力图。

### 3.3 算法机制与方法体系

9. 数学规划、规则、进化计算、强化学习、路径规划及混合方法谱系。
10. 算法机制卡片：输入、计算、输出、作用环节、成本和失效条件。
11. 机制—问题匹配矩阵。
12. 代表方法完整流程图与跨论文方法比较表。

### 3.4 评价与实验

13. 目标函数和评价指标字典。
14. 数据集、算例及公开性地图。
15. 实验预算、对照算法、重复次数、统计方法和公平性比较表。
16. 可复现性、证据强度和实验风险评价。

### 3.5 综合成果

17. 跨论文对比矩阵。
18. 主流共识、矛盾及适用条件分析。
19. 研究空白清单。
20. 可迁移机制与可运行基线优先级。
21. 候选研究路线、验证实验和失败出口。
22. AGV 智能调度文献综述报告。
23. 面向当前研究选择的决策报告。

## 4. 成果生成依据

每项正式结论至少记录以下依据：

1. Notion 中对应记录及字段。
2. `paper` 仓库中的原文文件和可定位段落。
3. DOI、出版社、期刊、会议或权威书目数据源的核验结果。
4. 分类、比较或评价所采用的明确规则。
5. 已验证事实、作者主张、分析推断和研究建议的不同证据状态。

正式综合采用以下纪律：

- 先冻结研究问题，再检索和综合。
- 算法名称与实际机制分开描述。
- 矛盾结论分析数据、场景、约束和实验条件，不直接平均。
- “没有检索到”不能直接写成“没有研究”。
- 结论强度不得超过证据强度。
- 可运行不等于复现等价；代码、数据和协议分别评价。

## 5. 九节点状态机

状态枚举为：`未开始`、`进行中`、`待验收`、`已验收`、`受阻`。

### N1 资料接入与资产盘点

- 输入：Notion 数据库、GitHub 文献原文。
- 动作：盘点资产，匹配 Notion 记录与原文，识别重复、缺失和版本。
- 成果：资产清单、Notion—GitHub 对应表、异常清单。
- 验收：每条记录都有“已匹配、缺原文、待确认”之一；仓库原文无改动。

### N2 元数据与证据核验

- 输入：N1 对应表及原文。
- 动作：核验书目信息和 Notion 结论的原文依据。
- 成果：书目核验表、证据定位表、未核验事项。
- 验收：正式使用的文献可定位；推断与原文结论分离。

### N3 研究问题与范围冻结

- 输入：N1、N2 的可靠语料。
- 动作：构建问题树，收敛研究问题和排除项。
- 成果：RQ Brief、范围说明、术语表。
- 验收：每个 RQ 可由文献证据回答，结论能够逐项回应。

### N4 问题情境分类

- 输入：冻结的 RQ 和已核验文献。
- 动作：按场景、资源、决策、扰动和约束分类。
- 成果：分类体系、情境—决策矩阵、覆盖图。
- 验收：全部纳入文献可归类；分类轴定义一致。

### N5 算法机制与方法体系

- 输入：情境分类和论文方法描述。
- 动作：拆解输入、计算、输出、作用环节和失效条件。
- 成果：算法谱系、机制卡片、流程图、匹配矩阵。
- 验收：每个机制说明解决什么、不解决什么；代表算法调用链完整。

### N6 评价指标与实验体系

- 输入：论文模型、实验和结果章节。
- 动作：统一指标口径，比较算例、预算、对照、统计和可复现性。
- 成果：指标字典、算例地图、实验协议矩阵、风险报告。
- 验收：不同指标变体被区分；所有性能比较注明条件和预算。

### N7 证据综合与研究评价

- 输入：N4 至 N6 的结构化成果。
- 动作：跨论文比较，分析共识、矛盾、条件和证据强度。
- 成果：对比矩阵、共识与争议报告、证据评价。
- 验收：存在实质跨论文比较；评价均可追溯；措辞与证据匹配。

### N8 研究空白与决策转化

- 输入：N7 综合结果及定向补充检索。
- 动作：形成空白、可迁移机制、基线和候选研究路线。
- 成果：空白清单、基线优先级、候选路线、验证实验和失败出口。
- 验收：空白经过补充检索；每条路线有问题依据、对照和失效条件。

### N9 成果编译、审查与发布

- 输入：全部已验收阶段成果。
- 动作：编译综述和决策报告，执行引用、数字和图文一致性检查。
- 成果：最终综述、研究地图、决策报告、仪表盘快照。
- 验收：引用均有核验状态；RQ 逐项回答或标明证据不足；成果已提交仓库。

## 6. 仪表盘字段

`DASHBOARD.md` 中每个节点固定显示：

| 字段 | 含义 |
|---|---|
| 状态 | 五种状态之一 |
| 进度依据 | 已完成项与总项，不凭主观估百分比 |
| 当前输入 | 本节点实际使用的材料 |
| 永久成果 | 已提交文件链接 |
| 临时检查 | 当前需要用户查看的过程材料 |
| 未决问题 | 阻碍判断或验收的事项 |
| 验收条件 | 本节点固定门槛 |
| 验收结论 | 未验收、通过、带限制通过或不通过 |
| 最近更新 | 日期和对应 Git 提交 |

控制台只报告可复核状态。节点进入“已验收”必须有用户确认或预先批准的客观验收规则及对应证据。

## 7. 临时日志生命周期

过程日志用于展示检索候选、匹配歧义、核验失败和中间计算，不作为永久研究成果。

1. 临时日志保存在本地工作目录，不加入 Git。
2. 仪表盘只显示“有待查看日志”及其用途，不复制日志全文。
3. 用户查看后明确表示无需保留，即删除对应临时日志。
4. 删除前确认永久成果已吸收必要证据、决定和限制。
5. Git 提交历史、正式验收结论和支撑正式结论的证据表不得作为临时日志删除。

## 9. 变更与发布规则

- 研究成果按节点分批提交，每次提交说明新增证据、结论和限制。
- 原始文献只读，任何整理需求另行确认。
- 修改分类轴、RQ、评价口径或验收门槛时，在仪表盘记录原因和影响。
- 未通过节点验收时，可以继续无依赖的工作，但不得把该节点标为完成。
- 不向 `paper-explaination` 写入本工作流的任何文件。
