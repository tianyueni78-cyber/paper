# 23｜我的文献脉络总图

> 用途：给未来的我，不是给审稿人。目标是在 10–20 分钟内重新恢复整个研究脉络。

## 1. 这个领域最初在解决什么？

最底层问题不是“怎么用 LLM”，而是：**如何更自动地求解复杂优化问题，以及如何自动决定该用什么模型、heuristic、operator、algorithm 或 solver component。**

传统路线里，很多关键决策由人完成：建模、选算法、设计 heuristic、选 neighborhood、调参数、根据状态切换策略。78、79 给出了 automated design / selection / ML4CO 的基础背景。

关键 Paper IDs：`78,79`

## 2. 为什么旧方法不够？

固定 heuristic 或固定 operator 在稳定环境里简单、快，但遇到实例分布、动态事件、搜索阶段和瓶颈变化时适应性有限。AOS / HH / RL 把“选哪个策略”提升为高层决策问题，但仍常依赖人工 feature/state/reward 设计。

关键 Paper IDs：`78,65`

## 3. 技术经历了哪些关键变化？

可以把演进压缩成七步：

1. 固定 heuristic / solver。
2. HH / AOS：从有限策略库中选择。
3. RL / Q-learning：从交互数据学习 state-action-effect。
4. LLM direct solving / formulation：LLM 直接给解，或生成模型/代码再交 solver。
5. LLM heuristic generation：让 LLM 设计可重复执行的 heuristic。
6. Search-aware AHD：LLM 不只生成，还读取 trajectory、diversity、uncertainty、runtime 管理设计搜索。
7. Contextual / supervisory control：LLM 根据 current state / history / constraint / scale 在线选择 heuristic、algorithm 或 action。

关键 Paper IDs：`73,77,69,68,05,07,43,44,45,23,37,58`

## 4. LLM 到底进入了哪些 Decision Layer？

至少可以区分：

- **Solution layer**：直接输出解。`36,61,63,73,75`
- **Modeling layer**：自然语言→数学模型/solver code。`38,48,51,56,59,60,62,64,66,67,71,74,76,77`
- **Heuristic generation layer**：生成 heuristic。`03,25,26,68,69`
- **Operator / system design layer**：设计多个 operator、solver component 或完整算法。`06,16,30,50`
- **Search-control layer**：管理 heuristic-design search。`05,07,40,43,44,45`
- **Selection layer**：从已有 heuristic / algorithm / action 中选择。`23,37,58`
- **Dynamic scheduling decision layer**：在动态调度状态下进行战略或即时决策。`19`

## 5. generation 和 selection 有什么本质区别？

**Generation** 改变候选策略空间本身：生成新的 heuristic / operator / code。

**Selection** 不创造新策略，而是在给定策略库里决定“此时用哪个”。

这两个问题的实验控制完全不同。若研究 selection，必须固定 strategy library，否则无法判断提升来自 selector 还是新策略本身。

关键 Paper IDs：`69,68,18` 对照 `23,78`

## 6. offline design 和 online control 有什么区别？

**Offline design**：在部署/求解前，用 LLM 搜索、演化或生成 heuristic/policy，最终输出一个快速执行的策略。

代表：`69,68,09,18`

**Online control**：求解过程中，根据当前状态反复决策下一步用哪个 heuristic / action。

代表：`23,58,19`

真正争议不是谁“更智能”，而是：online control 是否值得其 latency / token / stability 成本。09 是重要反向证据。

## 7. environment state 和 search-process state 有什么区别？

**Environment state** 描述外部问题现在是什么样：

- 新工件到达；
- 机器故障；
- AGV 拥堵；
- 当前未完成任务；
- 当前资源可用性。

相关：`19,23,58`

**Search-process state** 描述优化器自己现在搜到什么阶段：

- convergence / stagnation；
- population diversity；
- uncertainty；
- parent lineage；
- Pareto front 状态；
- 剩余评价预算；
- 前一策略效果。

相关：`05,07,43,44,45,21,54`

当前研究最可能的差异恰好在于：把两类 state 放进同一个 supervisory selector，而不是只看其中一类。

## 8. Pareto-aware 到底可以分成哪几种？

至少要区分三层，不能都叫“多目标”：

1. **问题目标是多目标**：例如 makespan + TEC。
2. **heuristic design 本身做 Pareto optimization**：例如寻找非支配 heuristic set。`21,54`
3. **运行时 selector 读取 Pareto front 状态并据此给策略 credit**：这是当前仍需重点核验的机制。

第 1 和第 2 已明显存在，不能直接拿来当 novelty；第 3 才可能是当前真正需要查证和实验的点。

## 9. 哪几篇是关键转折点？

- `78`：把 automated design / selection / AOS / HH 的方法边界讲清。
- `69 EoH`：LLM+EC heuristic generation 的代表起点。
- `68 ReEvo`：把 verbal reflection 与 performance feedback 引入 heuristic evolution。
- `18 EoH-S`：从单 heuristic 推进到 heuristic set。
- `05 PathWise`：trajectory / memory / world model 进入 heuristic-design search。
- `07 DASH`：trajectory-aware convergence + runtime schedule。
- `23 HeurAgenix`：state-aware online LLM heuristic selection，直接进入 selection HH。
- `19 ReflecSched`：LLM 已进入 dynamic FJSP strategic decision。
- `58 Wireless Power Control`：state-action-reward history → online LLM decision。
- `09 TPET`：强调 slow LLM / fast policy 的现实 latency 路线。

## 10. 哪几篇直接卡住我的创新？

第一梯队：

- `23 HeurAgenix`：卡住“LLM heuristic selector”。
- `19 ReflecSched`：卡住“LLM + dynamic FJSP”。
- `58 Wireless Power Control`：卡住“history-aware online LLM decision”。
- `09 TPET`：卡住“在线 LLM 一定适合实时控制”的默认假设。

第二梯队：

- `05,07,43,44,45`：卡住“search-process awareness 是新的”。
- `21,54`：卡住“Pareto-aware design 是新的”。
- `18,06`：卡住“portfolio / multi-operator 是新的”。

## 11. 我的研究现在站在哪里？

当前最准确的位置不是：

> LLM 替代 Q-learning。

而是：

> **在动态多目标 FJSP-AGV 中，固定底层 NSGA-II、decoder 和策略库，让 LLM 作为高层 supervisory selector，同时读取环境状态与搜索过程状态，并与 Q-learning 做严格单模块、同真实解码预算比较。**

进一步可研究：

- Pareto-aware strategy credit；
- delayed / trajectory-level strategy effect；
- remaining-budget-aware selection；
- unseen dynamic-event / scale generalization；
- quality gain 与 inference latency/cost 的 break-even boundary。

## 12. 目前真正还没有被证实解决的问题是什么？

不是“有没有人用 LLM”。那艘船早开走了。

当前最值得追的未证实问题是：

> 在**相同低层搜索空间与评价预算**下，联合读取 dynamic environment state、search-process state、Pareto state、historical strategy effect 与 remaining budget 的 LLM supervisory selector，是否真的比 Q-learning / strong rule / AOS 更好；如果更好，收益究竟来自哪种信息，是否能跨事件和规模泛化，并是否值得它的推理成本。

证据状态：`【分析判断｜中等置信】`。

会改变判断的证据：

1. 找到高度同构的 direct competitor；
2. Scheduling Corpus 出现更直接机制；
3. 预实验显示 richer context 无稳定增益；
4. strong rule / AOS 已达到同等结果；
5. LLM latency/cost 使在线控制不现实。
