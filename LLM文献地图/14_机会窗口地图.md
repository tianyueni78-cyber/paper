# 14｜机会窗口地图

> 版本：V1（基于 `LLM/` 69 篇正文）
>
> 目标：寻找“前置条件已成熟，但关键能力尚未稳定解决”的研究机会。这里不把“别人没做过某对象”当强 gap，而优先寻找机制和能力缺口。

## 结论先行

【分析判断】基于现有 69 篇文献，最值得用户当前课题进入的不是“LLM + 动态调度”这个大标签，也不是“LLM selector”本身，而是下面这个更窄、更可检验的机会：

> **在固定低层策略库和固定多目标优化器中，让 LLM 作为高层 contextual selector，同时读取动态调度环境状态、搜索过程状态、Pareto 状态、历史策略效果与剩余评价预算，并与 Q-learning selector 做严格单模块、同预算替换比较。**

这不是已确认 novelty，而是当前证据支持度最高、同时仍需继续核验直接竞品的候选窗口。

# Opportunity 1｜动态多目标搜索中的“环境状态 + 搜索状态”统一高层选择

## 机会定义

现有相关研究分别证明了：

- LLM 能按 current problem state 在线选 heuristic：HeurAgenix（23）；
- LLM 能利用 `(state, action, reward)` history 在线决策：Wireless Power Control（58）；
- LLM 能在 dynamic FJSP 中通过反思获得 strategic experience：ReflecSched（19）；
- AHD 研究正在利用 trajectory、uncertainty、diversity、runtime：PathWise（05）、DASH（07）、QUBE（44）、HSEvo（45）、MCTS-AHD（43）；
- multi-objective heuristic design 已开始考虑 Pareto / trade-off：MEoH（54）、MPaGE（21）。

但这几类信息通常**分散在不同研究路线**。

## 已成熟的前置条件

1. LLM 能处理结构化文本 context；
2. 低层 strategy/operator library 可固定；
3. 原 NSGA-II / decoder 已有稳定执行框架；
4. dynamic event 与 search statistics 可计算；
5. HV、makespan、TEC、decode count 可作为客观反馈；
6. Q-learning 原 selector 提供天然同模块 baseline。

## 当前能力边界

【文献归纳】当前文献已经覆盖单独的 state-aware selection、history-aware decision、dynamic scheduling reflection、trajectory-aware AHD；但现有库中尚未观察到一篇论文把以下信息在**动态多目标 FJSP-AGV 的固定 optimizer selector 层**统一起来：

- dynamic event / machine / AGV state；
- search stage；
- Pareto stagnation / diversity；
- previous strategy effect；
- strategy history；
- remaining real-evaluation budget。

这是【待验证】而不是“尚无研究”结论。

## 可验证 RQ

> **RQ1:** Under an identical low-level strategy library, decoder, dynamic-event process, and real evaluation budget, can an LLM-based contextual selector exploit joint environment-and-search-state information to outperform a Q-learning selector in dynamic multi-objective FJSP-AGV?

## 推荐实验

Selector：

- Fixed strongest strategy
- Random
- Rule-based
- Q-learning
- LLM-contextual

Context ablation：

- C0 动态事件状态
- C1 + 搜索阶段
- C2 + Pareto 停滞/多样性
- C3 + 历史策略效果
- C4 + 剩余真实解码预算

Metrics：

- HV
- makespan
- TEC
- real decoding / evaluation count
- selector decision latency
- LLM call/token cost
- infeasible / invalid decision rate
- cross-instance / cross-event generalization

## 主要风险

- HeurAgenix 已占据“state-aware online heuristic selection”；
- ReflecSched 已占据“dynamic FJSP + LLM strategic decision”；
- 58 已占据“history reward + online LLM decision”；
- 如果 richer context ablation 没有稳定增益，机制贡献会坍缩成“换 selector”。

## 评分

| 维度 | 评分 | 判断 |
|---|---:|---|
| Evidence | ★★★★★ | 多条直接/近邻证据已出现 |
| Novelty | ★★★★ | 必须依靠联合 context + 模块级比较，而非 LLM selector 本身 |
| Momentum | ★★★★★ | online selection、trajectory-aware、dynamic LLM 均在加速 |
| Feasibility | ★★★★★ | 可复用现有 optimizer / decoder / strategy library |
| Evaluation | ★★★★★ | 天然可做同模块同预算实验 |
| Relevance | ★★★★★ | 与当前 FJSP-AGV 原 Q-learning 架构直接衔接 |
| Durability | ★★★★ | 本质问题是 supervisory control，不依赖单一模型热点 |

**综合：★★★★★，但 novelty 必须继续收窄和补证。**

# Opportunity 2｜LLM selector 的长期 credit assignment，而不是只看即时 reward

## 机会定义

Q-learning 通常通过 scalar reward 更新 state-action value；LLM 系统则可能读取更丰富的历史：

- 最近若干策略选择；
- 每次选择后 Pareto front 的变化；
- bottleneck 是否转移；
- 短期无改善但后续是否带来新区域探索；
- 某策略在不同 search stage 的 delayed effect。

## 为什么现在可做

- ReEvo 已证明 verbal reflection 可积累长期 heuristic insights；
- PathWise / MCTS-AHD / Planning of Heuristics 把 heuristic search 视为 trajectory / planning；
- TPET 的 CAF 直接处理 micro-decision → macro-outcome 的 credit assignment；
- 当前动态优化器本身可以记录策略轨迹与后续指标变化。

## 未解决能力

【分析判断】真正有研究价值的不是“把过去 reward 塞进 prompt”，而是：

> 如何把一个高层策略的延迟效果归因给它，并形成可复用的策略经验？

## 可验证 RQ

> **RQ2:** Does trajectory-level strategy-effect feedback improve high-level selection beyond immediate one-step reward in dynamic multi-objective search?

## 实验建议

比较：

- immediate reward only
- rolling-window effect
- delayed HV contribution
- structured verbal summary of strategy effect

同时控制相同 history length 和调用预算。

## 风险

credit 设计如果高度手工化，可能只是把 Q-learning reward shaping 换成 prompt shaping。

## 综合评分

**★★★★☆**

# Opportunity 3｜Pareto-aware 高层策略反馈

## 机会定义

用户问题本身是 makespan + TEC，多目标优化不能简单把高层策略效果压成一个随意加权 scalar reward。

MEoH / MPaGE 已说明 heuristic design 本身可以采用 Pareto 视角，但这与“动态搜索过程中如何给 selector credit”不是同一件事。

## 潜在能力缺口

高层 selector 应该理解：

- 当前 Pareto front 哪一段停滞；
- diversity 是否塌缩；
- 某策略改善 makespan 是否以 TEC 为代价；
- 当前更缺 exploitation 还是 front expansion；
- 某策略对 HV 的贡献是否来自真正扩展 front。

## 可验证 RQ

> **RQ3:** Can Pareto-state-aware contextual selection produce a better convergence-diversity trade-off than scalar-reward selector policies under the same decoding budget?

## 推荐比较

- weighted-sum reward Q-learning
- HV-increment reward Q-learning
- rule selector using stagnation/diversity
- LLM with structured Pareto context

## 风险

如果 Pareto features 本身足够简单，rule-based selector 可能已经做得很好。必须把 Rule baseline 做强，否则论文容易证明一个稻草人输给 LLM。

## 综合评分

**★★★★☆**

---

# Opportunity 4｜Budget-aware selector：决定“现在值得花哪种搜索预算”

## 机会定义

DASH、Hercules、LLaMEA-HPO 等都把 evaluation/runtime/token cost 从附属指标提升为设计问题。

用户当前实验也明确需要真实 decoder budget 公平。

## 研究问题

不是单纯“选哪个 operator”，而是：

> 在剩余预算不同、search stage 不同的情况下，同一个策略是否仍值得调用？

例如：

- 预算充足时允许高探索策略；
- 末期预算紧张时优先 exploitation；
- 若 LLM 推理本身昂贵，是否应降低调用频率。

## 可验证 RQ

> **RQ4:** Does explicit remaining-budget context improve the efficiency of adaptive strategy selection under fixed real decoding budgets?

## 风险

容易退化成简单 schedule rule，因此必须与强 rule / adaptive schedule 比较。

## 综合评分

**★★★★**

# Opportunity 5｜Slow LLM + Fast Selector / Rule 的分层架构

## 为什么出现

TPET 已直接提出 online LLM actor 的 latency 问题；动态生产调度同样可能要求低延迟。

## 候选结构

```text
低频 LLM：
分析最近 trajectory / dynamic event / bottleneck
→ 更新策略规则或小型 selector policy

高频执行层：
轻量 rule / learned policy
→ 每次快速选择 operator
```

## 可验证 RQ

> **RQ5:** Under equivalent optimization budgets, can a low-frequency LLM supervisory layer retain most of the adaptation benefit of online LLM selection while substantially reducing inference latency and cost?

## 价值

如果 online LLM 结果好但成本太高，这会自然成为第二阶段工作；如果 online LLM 本身没有增益，就没有必要过早复杂化。

## 综合评分

**★★★☆**，有前景但不建议作为第一版主创新。

---

# Opportunity 6｜跨动态事件 / 规模的零训练或低训练泛化

## 背景

传统 RL selector 的潜在弱点是 state/reward/training 与任务分布绑定；LLM 的潜在优势则是可以根据文本化/结构化 context 直接解释新情形。

但这是一个**假设**，不能因为 LLM 会说话就默认成立。

## 可验证 RQ

> **RQ6:** Does an LLM selector generalize to unseen dynamic-event combinations or instance scales with less retraining than a Q-learning selector?

## 实验

训练/设计阶段不暴露某类事件组合，例如：

- unseen breakdown frequency；
- unseen job-arrival intensity；
- unseen AGV congestion level；
- larger instance scale。

测试 Q-learning 是否需要重训，以及 LLM zero/few-shot context adaptation 的性能。

## 风险

LLM 也可能因为数字/结构推理不足而泛化更差。

## 综合评分

**★★★★**

# 不建议作为主创新的“伪机会”

## 1. “LLM 用于动态调度”

**否。** ReflecSched 已直接进入 dynamic FJSP。

## 2. “LLM 从 heuristic pool 选择 heuristic”

**否。** HeurAgenix 已明确这样做。

## 3. “LLM 根据历史 reward 决策”

**否。** 58 号无线功控已有 experience pool `(state, action, reward)`。

## 4. “LLM 自动生成 heuristic”

**高度拥挤。** EoH、ReEvo、FunSearch 相关生态已经非常成熟。

## 5. “LLM + multi-objective”

**过宽。** MEoH、MPaGE、E2OC 已经覆盖多个角度。

## 6. “LLM 比 Q-learning 更智能”

不是学术问题。必须具体成 state representation、credit assignment、generalization、budget efficiency 中至少一个可测能力。

# 当前推荐的主研究命题

## 中文

> **面向动态多目标 FJSP-AGV 的搜索过程感知 LLM 高层策略选择：在固定低层策略库和固定 NSGA-II 执行器条件下，利用动态事件、Pareto 搜索状态、历史策略效果与剩余预算进行上下文策略选择，并与 Q-learning 高层选择器开展同模块、同真实解码预算的公平比较。**

## 英文工作表述

> **Search-Process-Aware LLM Contextual Selection for Dynamic Multi-Objective FJSP-AGV:** evaluating whether an LLM supervisory selector can exploit dynamic environment state, Pareto-search state, historical strategy effects, and remaining evaluation budget to outperform a Q-learning selector under an identical strategy library, optimizer, decoder, and real evaluation budget.

## 注意

这只是当前文献库支持的**候选定位**，不是 novelty claim。

# 最关键的下一轮补证问题

不是继续搜“LLM scheduling”，而要专门查以下几个判断：

1. 是否已经存在 **LLM + online operator selection inside evolutionary search** 的直接论文？
   - 会决定 Opportunity 1 的 novelty 强弱。

2. 是否已有 **LLM selector vs RL/AOS selector under identical operator library** 的公平实验？
   - 会决定当前 comparison 是否仍有空位。

3. dynamic FJSP/FJSP-AGV 中是否已有显式利用 **search-stage / Pareto-state / operator-history** 的 LLM controller？
   - 会决定 context 组合是否真正新。

4. 在线 LLM 调度论文如何计入 inference latency / API cost？
   - 会决定实验协议是否必须加入 wall-clock / token cost。

5. 多目标 HH/AOS 文献如何定义 operator credit？
   - 会决定 Pareto-aware feedback 应该如何设计，而不是凭 prompt 想象。

这些检索会真正改变研究判断，因此优先级高于继续扩大普通论文数量。
