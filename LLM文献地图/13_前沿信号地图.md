# 13｜前沿信号地图

> 版本：V1（基于 `LLM/` 69 篇正文）
>
> 目的：判断哪些方向在形成可持续研究子领域，哪些只是几篇论文的短期热闹。
>
> 分级：A 强前沿｜B 正在形成｜C 弱信号｜D 概念性。

## 结论先行

【文献归纳】当前最强的信号不是“LLM 用于优化”这一大标签，而是五个更具体的迁移：

1. **从直接生成结果 → 生成/设计可执行算法**；
2. **从单次提示 → 搜索、反思、记忆和验证闭环**；
3. **从单一 heuristic → portfolio、multi-operator、full solver component**；
4. **从 endpoint score → trajectory、uncertainty、diversity、runtime、budget**；
5. **从静态离线设计 → contextual selection、动态决策与 slow/fast hybrid control**。

# A1｜LLM-driven Automatic Heuristic / Algorithm Design

**前沿等级：A｜强前沿**

## 时间密度

2024–2026 在库文献高度集中：EoH（69）、ReEvo（68）、HSEvo（45）、QUBE（44）、MCTS-AHD（43）、MEoH（54）、EoH-S（18）、Hercules（26）、AutoRNet（50）、EvoPlace（30）、CVRP-AHD（03）等。

## 独立团队

多所高校与不同研究团队独立推进，不是单一团队连续发文。

## 方法分化

已经形成：

- LLM + evolutionary search；
- reflection；
- uncertainty-aware selection；
- diversity management；
- MCTS planning；
- multi-objective heuristic design；
- heuristic set design；
- whole-algorithm / solver-component generation；
- performance prediction / evaluation acceleration。

## benchmark / survey 信号

22、15、52、78 等综述已从不同角度系统整理 LLM4CO、LLM+EA、algorithm design 与 metaheuristic design。

## 从 Demo 到系统

开始显式讨论：

- token / API cost（53）；
- sample efficiency（68、26）；
- search diversity（45）；
- uncertainty（44）；
- runtime / efficiency（21、54）；
- industrial solver components（16、30）。

## 判断

【分析判断】“再做一个 EoH 变体，只换 prompt”已经明显拥挤。真正还有价值的是**搜索机制、系统级设计、泛化、动态适应与成本约束**。

# A3｜Search-process-aware LLM Optimization

**前沿等级：A- / B+｜强烈上升**

## 代表文献

PathWise（05）、DASH（07）、MCTS-AHD（43）、Planning of Heuristics（40）、QUBE（44）、HSEvo（45）、ReEvo（68）、Hercules（26）、OPRO（73）。

## 重复出现的关键词背后是同一个机制问题

不是简单“加 memory”，而是研究：

- 当前搜索处于哪里；
- 过去哪些尝试有效；
- 哪些区域尚未探索；
- 当前不确定性多大；
- 何时应 exploration / exploitation；
- 搜索轨迹是否正在停滞；
- 剩余预算应该怎么花。

## 为什么是前沿

早期 LLM optimization 把每次 generation 当局部事件；现在越来越多工作把整个优化过程建模为**有状态序列决策**。

## 仍缺什么

- 跨问题的统一 state 表达；
- search-state 与 environment-state 如何结合；
- long-horizon credit assignment；
- 同预算下是否真的优于简单 AOS / RL。

## 对当前研究

这是最值得吸收的前沿之一，因为用户方案的潜在价值恰好不在“LLM”本身，而在**把 dynamic environment state 与 search process state 合并后做高层选择**。

# B1｜Heuristic Portfolio / Multi-operator / System Co-design

**前沿等级：B+｜正在形成，接近 A**

## 代表文献

EoH-S（18）、E2OC（06）、MEoH（54）、MPaGE（21）、AutoPBO（16）、EvoPlace（30）、HeurAgenix（23）。

## 信号

- 单 heuristic 跨实例泛化不足已被明确提出；
- 多 heuristic complementarity 开始成为显式目标；
- operator interdependence 开始被建模；
- multi-objective heuristic design 开始同时考虑性能与效率；
- 自动设计范围从 scoring function 扩展到完整 solver component。

## 下一步自然问题

一旦有“策略集合”，真正重要的问题就变成：

> 何时选择哪一个？

这正推动 contextual selection 与 online hyper-heuristic 重新变热。

# B2｜LLM Contextual Selection / Supervisory Control

**前沿等级：B+｜正在快速形成**

## 代表证据

- HeurAgenix（23）：problem-state-aware online heuristic selection；
- MA-GTS（37）：problem-aware algorithm selection；
- Wireless Power Control（58）：state + experience pool + reward 的在线 in-context decision；
- ReflecSched（19）：dynamic FJSP 中 hierarchical reflection + strategic decision；
- 65 号短综述/position work 已把 LLM-assisted evolutionary strategy selection 作为明确方向讨论。

## 为什么不是 A

当前证据已经说明方向存在，但：

- 应用对象分散；
- evaluation protocol 不统一；
- latency / cost 是否计入不统一；
- 与经典 AOS、Bandit、RL/Q-learning 的直接公平比较还不系统；
- 对“什么时候在线调用 LLM、什么时候应离线生成 fast policy”仍无稳定共识。

## 判断

这是用户研究最接近的前沿，但也是最危险的地方：**方向不是空白，必须做机制级差异。**

---

# B3｜Dynamic / Slow-Fast Hybrid LLM Control

**前沿等级：B｜正在形成**

## 代表信号

- ReflecSched（19）：动态 FJSP + strategic reflection；
- TPET（09）：明确反对高频 online LLM actor，转而用 LLM 演化轻量 policy；
- Wireless Power Control（58）：动态环境中 in-context online decision；
- DASH（07）：distribution shift / re-adaptation / runtime schedule；
- Agentic / tool-augmented systems开始将慢推理与快执行分层。

## 核心争议

### 在线 LLM

优点：上下文丰富、可即时解释、无需训练或少训练。

缺点：latency、API cost、稳定性。

### 离线/低频 LLM + 快速规则

优点：在线快、部署稳定。

缺点：环境剧烈变化时需要重新生成/更新规则。

### LLM + RL / Agent hybrid

潜力大，但系统复杂、credit assignment 更难。

## 判断

【分析判断】未来更像是“LLM 什么时候该被调用”的问题，而不是“是否使用 LLM”。

---

# B4｜Multi-objective LLM-based Algorithm Design

**前沿等级：B｜正在形成**

## 证据

MEoH（54）、MPaGE（21）、E2OC（06）已经明确从单目标 heuristic performance 扩展到 multiple objectives、Pareto trade-off、operator interaction。

## 注意

这里的“multi-objective”常常指**设计 heuristic 时的多个标准**，不等于用户的底层调度问题本身就是 makespan + TEC。

## 未稳定问题

- 如何把 optimization-process indicators 纳入高层 decision；
- Pareto front state 如何转成 selector context；
- 高层策略效果如何在多目标下做 credit assignment。

这对当前研究非常有价值。

---

# B5｜Benchmark / Evaluation Maturation

**前沿等级：B+｜基础设施型前沿**

## 证据

NL4Opt（77）、Mamo（64）、DCP-Bench（24）、OptMATH（42）、GraphArena（61）、IndustryOR（62）、BWOR（33）等说明领域正从 demo 走向 standardized evaluation。

## 评价内容也在升级

从：

- final answer accuracy

到：

- feasibility；
- optimality；
- process correctness；
- solver verification；
- equivalence；
- runtime；
- token / query budget；
- generalization；
- real-world cases。

## 判断

任何声称“LLM 更好”的研究，如果不报告预算、延迟、失败率与重复实验，会越来越难站得住。

---

# C1｜Direct LLM Solving of Large CO

**前沿等级：C｜有研究价值，但作为通用方案信号较弱**

GraphArena、NLGraph 等已经提供反例：规模和结构复杂度提高后，LLM direct solving 的鲁棒性明显下降。

它仍然有研究价值，尤其作为：

- baseline；
- reasoning capability test；
- hybrid system component；
- small / semantic-rich problem solver。

但目前不适合被解释成“即将替代传统 solver / search”。

---

# 当前真正拥挤的方向

【分析判断】以下工作若只做轻量变体，创新风险较高：

1. 在 TSP/BPP 上再做一个 LLM+EA heuristic generator；
2. 只换 prompt / crossover / reflection 名称；
3. 单纯证明“LLM 能生成 heuristic”；
4. 单纯把 LLM 接到 solver 上生成 MILP code；
5. 单纯证明“LLM 能用于调度”；
6. 单纯证明“LLM 能根据 state 选择 heuristic”。

---

# 当前最值得盯的 5 个前沿信号

1. **Search-state / trajectory-aware decision**：从结果反馈升级到过程状态；
2. **Portfolio + contextual selection**：从生成一个策略升级到管理一组策略；
3. **Dynamic slow-fast hybrid**：LLM 与快速执行策略的分层频率设计；
4. **Multi-objective credit assignment**：高层策略如何在 Pareto 优化中获得反馈；
5. **Budget-aware fair evaluation**：把真实 evaluation、LLM query、latency 一起纳入比较。

这五个信号共同构成当前研究最值得进入的区域。
