# 01｜三层研究问题地图

## 一句话定位

本研究不是“让 LLM 直接求解调度”，而是研究 **LLM 能否作为动态多目标 FJSP-AGV 优化器之上的上下文感知高层策略选择器**。

---

# 第一层｜领域层

## 1. 一级领域

### A. 生产调度与组合优化
核心问题：在资源、工艺、运输和时间约束下构造高质量调度方案。

本研究涉及：
- Flexible Job Shop Scheduling Problem（FJSP）
- Dynamic FJSP（DFJSP）
- Machine–AGV integrated scheduling
- Multi-objective scheduling
- Energy-efficient scheduling

### B. 元启发式与多目标进化优化
核心问题：NP-hard 问题无法依赖精确算法大规模求解时，如何在有限预算下搜索高质量 Pareto 解集。

本研究当前底层执行框架：NSGA-II + 编码/解码 + 局部搜索/策略库。

### C. Hyper-Heuristic / Algorithm Selection / Adaptive Operator Selection
这是当前最需要补齐的理论祖先。

核心问题不是直接搜索调度解，而是：

> 面对当前问题状态或搜索状态，应该选择哪个低层 heuristic/operator/algorithm？

经典 hyper-heuristic 区分 selection 与 generation 两大类。本研究更接近 **selection hyper-heuristic**，而现有大量 LLM4AHD 工作更接近 heuristic generation/design。

### D. Reinforcement Learning for Search Control
Q-learning 等 RL 方法可作为高层控制器，根据状态、动作和奖励学习策略选择规律。

本研究原方案属于：

`state → Q-learning selector → low-level strategy → optimizer`

### E. LLM for Optimization / LLM-driven Heuristic Design
近年形成的研究路线包括：
- heuristic / algorithm generation
- operator design
- multi-operator co-design
- solver adaptation
- policy generation
- LLM + RL
- LLM online decision making

本研究拟进入其中较窄的一格：**context-aware high-level strategy selection**。

## 2. 方法演进的初始骨架

`人工规则/固定算子`
→ `Hyper-Heuristic / Algorithm Selection`
→ `Adaptive Operator Selection`
→ `RL / Q-learning 高层选择`
→ `LLM-driven heuristic generation/design`
→ `LLM-based contextual search control（待充分验证）`

注意：最后一步目前是候选研究方向，不能写成已形成成熟范式。

---

# 第二层｜问题层

## 1. 现实问题

动态制造环境中，机器故障、任务到达、运输拥堵、资源状态变化等事件会使原计划失效；同时 FJSP-AGV 存在机器与运输资源耦合，单一固定搜索策略未必在所有搜索阶段、事件类型和瓶颈结构下都有效。

## 2. 学术问题

核心不是“怎样再设计一个邻域”，而是：

> **什么时候应该使用哪个已有策略？**

这对应 selection hyper-heuristic / adaptive operator selection / search control。

## 3. 已有主要解决路线

### 路线 A｜固定策略或人工规则
优点：便宜、稳定、可解释。
局限：难随搜索阶段和动态环境变化自适应。

### 路线 B｜自适应概率/credit-based operator selection
根据历史效果更新算子概率或得分。

### 路线 C｜RL / Q-learning selector
显式定义 state/action/reward，通过交互学习低层策略选择。

已核验的直接近邻包括 Zhang et al. (2023) 的 Q-learning hyper-heuristic，用高层 Q-learning 从预设计 LLH 集合中选择策略解决带运输资源的 distributed FJSP。

### 路线 D｜LLM 自动生成/设计 heuristic
EoH、LLaMEA 等代表工作主要回答“如何生成或改进 heuristic/algorithm”。

### 路线 E｜LLM 多算子设计与 solver adaptation
E2OC 关注 interdependent operator co-design；DASH 关注 convergence trajectory 与 profile-aware solver adaptation。

### 路线 F｜LLM 生成策略或参与动态决策
TPET 使用 structured state abstraction 和反馈来演化轻量策略；FJSP 中也已出现 LLM 增强 DRL 的路线。

## 4. 当前真正的分歧

不是“LLM 能不能用于优化”，这个问题已经太宽。

真正需要比较的是：

- LLM 应该 **生成新 heuristic**，还是 **选择已有 heuristic**？
- LLM 应该 **离线设计**，还是 **在线控制**？
- LLM 应该 **替代 RL selector**，还是 **增强 RL 的 state/reward**？
- 更丰富的语义上下文是否值得额外推理成本和延迟？

# 第三层｜机制层

| 维度 | 当前候选设计 |
|---|---|
| 研究对象 | 动态多目标 FJSP-AGV |
| 输入信息 | 动态事件、机器/AGV状态、搜索过程状态、历史策略效果、预算 |
| 状态/上下文 | 结构化语义上下文，而非直接投喂全部裸数值 |
| 决策主体 | LLM 高层 selector |
| 决策变量 | 当前选择哪一个预定义策略/算子或策略组合 |
| 策略空间 | 固定策略库，具体组成待实验冻结 |
| 核心机制 | contextual strategy selection |
| 优化目标 | Makespan + Total Energy Consumption（TEC） |
| 动态事件 | 当前至少聚焦动态调度；具体事件集合需与实验模型一致 |
| 执行器 | 原 NSGA-II / 解码器 / 局部优化框架 |
| 反馈 | HV、目标改善、停滞、策略历史效果、真实解码预算等候选信息 |
| 核心对照 | fixed/random/rule-based、Q-learning selector、LLM selector |
| 评价指标 | HV、Makespan、TEC、真实解码次数；LLM 成本/延迟也应单列 |

## 方法到底改变什么？

尽量锁死：
- 编码
- 解码器
- NSGA-II 主体
- 动态事件定义
- 策略库
- 搜索预算
- 评价指标

主要替换：

`Q-learning high-level selector → LLM contextual selector`

## 数据流

`动态环境状态 + 搜索状态 + 历史反馈`
→ `结构化上下文`
→ `高层 selector`
→ `选择固定策略/算子`
→ `原优化器执行`
→ `解码与评价`
→ `反馈进入下一次决策`

---

# 当前证据边界

【原文事实】E2OC 明确研究 MOEA 中相互依赖 operator 的 co-design，并把 multi-operator optimization 表述为高层优化问题。

【原文事实】DASH 明确批评 endpoint-only evaluation，并利用 convergence trajectory 与 instance profile 进行 solver adaptation。

【原文事实】TPET 明确提出 Structured State Abstraction，并选择让 LLM 作为 policy discoverer，而非高延迟 online actor。

【我的归纳】这些工作共同支持“高层语义/策略层可以与底层优化执行层分离”，但不能直接证明“在线 LLM selector 优于 Q-learning selector”。

【待验证】LLM 在线从固定策略库选择 operator/heuristic 的直接近邻研究数量、成熟度与最佳实验协议。
