# 06｜一页研究定位

> 这页用于研究卡住时快速校准。随着证据变化持续改写，不把任何候选创新永久神圣化。

# 1｜领域现在主要研究什么？

本课题位于 **动态柔性作业车间调度 + 机器/运输资源协同 + 多目标进化优化 + Hyper-Heuristic / Adaptive Operator Selection + LLM for Optimization** 的交叉区域。

传统调度研究解决“如何构造更好的调度解”；selection hyper-heuristic 与 AOS 把问题抬高一层，研究“当前应该使用哪个低层 heuristic/operator”；RL/Q-learning 进一步通过状态、动作和奖励学习选择策略。近年的 LLM4Optimization 则大量进入 heuristic generation、operator design、solver adaptation、policy generation 以及 LLM+RL。

# 2｜主流方法如何演进？

`人工固定 heuristic`
→ `selection hyper-heuristic`
→ `adaptive operator selection`
→ `RL / Q-learning high-level selector`
→ `LLM-driven heuristic/operator generation`
→ `structured-state / dynamics-aware / LLM+RL adaptation`

当前真正值得研究的不是“LLM 能不能做调度”，而是 **LLM 在优化系统中应该处于哪一层、看到什么信息、控制什么模块，以及额外成本是否值得**。

# 3｜我和已有研究的连接在哪里？

### 理论连接
Selection Hyper-Heuristic / Adaptive Operator Selection：高层机制从低层策略库中选择 heuristic/operator。

### 直接传统方法连接
Q-learning HH 已用于带运输资源的 FJSP，并进一步出现在动态重调度、多目标能耗 FJSP 中。

### LLM 方法连接
- E2OC：多 operator 存在 interdependency，联合设计不能把 operator 完全孤立看待。
- DASH：solver evaluation 应关注 convergence trajectory、runtime 与 instance profile，而不只看最终 endpoint。
- TPET：raw numerical state 与 LLM 之间存在 semantic gap，可通过 structured state abstraction 处理；同时 online LLM actor 有 latency 风险。
- LLM4A3C：LLM 也可以增强 RL 的 state/reward，而不是替代 RL。

# 4｜最接近我的研究是谁？

当前不是某一篇论文完全同构，而是四组近邻共同包围：

1. **Q-learning selection HH + transport-coupled FJSP**：最接近原 selector 结构。
2. **dynamic / energy-aware Q-learning HH**：最接近动态、多目标与 state-action 设计。
3. **E2OC / DASH / TPET**：分别提供 operator interaction、search dynamics、structured context 的机制借力。
4. **LLM4A3C**：最重要的替代路线，证明“LLM + RL”不必等于“LLM 替代 RL”。

# 5｜真正还没有被当前证据解决的问题是什么？

【待系统检索确认】现有证据尚未充分覆盖这样一个组合机制：

> **固定底层优化器 + 固定策略库 + 结构化动态环境/搜索上下文 + LLM 高层策略选择 + 与 Q-learning selector 同预算直接比较。**

这个 gap 的价值不在“第一次把两个名词拼起来”，而在于它允许检验一个明确能力差异：

> LLM 的语义上下文处理能力，是否真的能改善传统 RL/HH 在复杂动态搜索状态下的策略选择？

# 6｜我的研究问题

> **在不直接修改底层优化器的前提下，LLM 能否利用动态调度事件、搜索过程状态与历史策略反馈，从固定策略库中进行上下文感知选择，并在相同求解预算下达到或超过 Q-learning 高层选择器？**

# 7｜当前创新假设

> **如果**将动态事件、搜索轨迹、瓶颈信息和历史策略反馈转换为稳定的结构化上下文，并由 LLM 承担固定策略库的高层选择，**那么**在动态多目标 FJSP-AGV 中，相比依赖人工 state/reward 设计的 Q-learning selector，理论上可能获得更好的情景适应性与解集质量；**但**该收益必须在相同真实解码预算下验证，并同时计入 LLM 延迟、token/API 成本、稳定性和泛化性能。

# 8｜当前实验最应该锁死什么？

尽量保持一致：
- encoding
- decoder
- NSGA-II backbone
- dynamic event definitions
- strategy/operator pool
- stopping criterion
- real decoding budget
- evaluation instances

主要改变：

`high-level selector`

至少比较：

`Fixed strongest strategy / Random / Rule-based or lightweight AOS / Q-learning / LLM`

# 9｜当前最危险的三个误判

1. **把“LLM 更新”当“LLM 更好”。** 新技术不是性能证据。
2. **把 AHD 文献当 selection 文献。** 生成 heuristic 与选择 heuristic 是两个研究问题。
3. **只比较最终 HV。** 如果 LLM 多花几十倍决策时间才提高一点 HV，论文结论会非常尴尬。

# 10｜下一轮文献工作只补什么？

优先级 P0：
1. Selection Hyper-Heuristic 奠基与现代综述。
2. Adaptive Operator Selection 经典机制、credit assignment、operator sequence。
3. Q-learning HH in FJSP / dynamic scheduling / transportation coupling。
4. LLM online heuristic/operator selection 的直接论文。
5. LLM vs RL / LLM-enhanced RL 的直接竞争证据。

暂时停止无差别增加普通 `LLM + heuristic generation` 论文，除非它提供了新的机制或直接竞争关系。

---

## 当前主席判断

**最值得投入实验验证的不是“LLM 能否用于调度”，而是“LLM 能否成为一个有成本优势或性能优势的 contextual selection hyper-heuristic”。**

置信度：**中**。

会改变判断的证据：找到高度同构先行研究；LLM 在线成本不可接受；Q-learning/轻量 AOS 在同预算下已足够；或 LLM-enhanced RL 明显优于直接替代 selector。
