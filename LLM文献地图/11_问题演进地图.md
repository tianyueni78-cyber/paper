# 11｜问题演进地图

> 版本：V1（基于 `LLM/` 中现有 69 篇正文交叉阅读）
>
> 目的：回答“这个领域究竟在解决什么问题，以及这些问题为什么一步步发生变化”。本文件不是逐篇摘要，而是用论文作为证据点维护问题演进链。

## 结论先行

【文献归纳】这批文献所覆盖的 LLM × Optimization / OR 研究，不是沿着一条单线发展，而是由两个老问题汇合后快速分叉：

1. **优化侧**长期想减少人工设计启发式、算子、参数与算法配置的成本；
2. **建模侧**长期想降低“自然语言业务问题 → 数学模型 → solver code”的专家门槛；
3. LLM 出现后，两条线都先尝试“直接生成”，随后暴露可靠性、规模、成本和泛化问题；
4. 近两年问题重心明显从“LLM 能不能做”转向“如何把 LLM 放到正确的决策层，并用搜索、反馈、验证、记忆、工具和快速执行器约束它”；
5. 最新一层问题已不是单个 heuristic 是否更好，而是**如何让一个可验证、可适应、成本可控的系统在动态环境和搜索过程中持续做正确的高层决策**。

---

# 阶段 0｜传统优化的基本矛盾：性能需要专家设计

## 核心问题

传统 exact / heuristic / metaheuristic 方法能够解决大量优化问题，但现实中的算法设计、参数配置、算子设计、模型构造仍高度依赖专家。

【原文事实】EoH（69）、ReEvo（68）、MEoH（54）、HSEvo（45）、AutoRNet（50）都把“手工 heuristic 设计耗时、依赖领域知识”作为直接动机。NL4Opt（77）、OptiMUS（67/59）、ORLM（62）则把“自然语言问题到数学模型仍依赖 OR 专家”作为另一条直接动机。

## 已解决

- exact solver、metaheuristic、局部搜索等已经提供成熟执行器；
- 人类可设计高质量算法与数学模型。

## 未解决

- 不同问题/环境需要重新设计；
- 参数、算子、建模形式和约束表达依赖人工；
- 难以低成本迁移。

## 问题状态

**成熟背景问题**。真正的研究重心已从“有没有算法”转向“如何减少专家干预”。

---

# 阶段 1｜自动化第一层：从人工设计到自动选择、配置与 Hyper-Heuristic

## 为什么出现

上一阶段已有大量低层算法，但“选哪个、怎么配、怎么组合”仍靠人。

【文献归纳】78 号综述明确区分 automated design、algorithm selection、AOS 与 hyper-heuristic；54 号 MEoH 也将传统 automated heuristic design 分成 configuration、selection、composition。

## 问题转移

从：

> 人工写一个更好的 heuristic

转向：

> 能否自动选择、配置或组合已有 heuristic / operator？

## 已解决

- algorithm selection、AOS、selection hyper-heuristic 已形成成熟概念；
- RL/Q-learning 等学习型 selector 可根据状态进行高层选择。

## 剩余问题

- 低层 heuristic space 通常仍由人定义；
- selector 常需训练，迁移后可能重训；
- 状态表达和 reward 设计依赖任务；
- 对动态复杂环境的泛化仍有限。

## 问题状态

**成熟但仍活跃**。它是后续 LLM selector 的直接理论祖先，而不是应该被 LLM 文献覆盖掉的旧东西。

---

# 阶段 2｜LLM 直接进入优化：能不能靠语言模型直接给答案？

## 代表证据

- OPRO（73）：LLM 根据历史 solution-score trajectory 迭代产生新解；
- NLGraph（75）、GraphArena（61）：系统评估 LLM 的图问题直接推理能力；
- STARJOB（36）：通过专门数据微调 LLM 端到端产生 JSSP 调度解；
- SGE（63）：用多条 reasoning trajectory、分解、反馈和整合直接解组合问题。

## 为什么出现

LLM 具备自然语言理解、代码生成、in-context learning 和一定推理能力，因此最直接的问题是：

> 能否绕过传统专家设计和专用算法，直接用 LLM 求解？

## 已解决

【文献归纳】小规模、结构较简单、可通过提示分解的问题上，LLM 确实能够产生可行甚至有竞争力的解。

## 暴露的新问题

【原文事实】GraphArena（61）和 NLGraph（75）都显示：随着规模和结构推理难度增加，LLM 的性能明显下降，出现 infeasible / hallucinated / suboptimal 输出；复杂问题上高级 prompting 的收益也会减弱。

因此问题从“能否直接解”转向：

> LLM 应该直接承担求解，还是应该只承担它真正擅长的高层语义/策略角色？

## 问题状态

**已证实可行但不适合作为通用主路线**。直接 LLM solving 是重要分支，但大型、强约束、动态优化中仍有明显上限。

---

# 阶段 3｜建模自动化：让 LLM 负责“理解”，让 solver 负责“计算”

## 代表演进

NL4Opt（77）
→ Auto Model Generator（76）/ Holy Grail 2.0（74）
→ OptLLM（60）/ OptiMUS（67）
→ ORLM（62）/ LLMOPT（51）
→ OptMATH（42）/ Mamo（64）/ EquivaMap（39）/ OR-LLM-Agent（33）/ OptiMUS-0.3（59）

## 核心问题如何变化

### 3.1 先解决“能否从自然语言抽出数学结构”

NL4Opt 将任务拆成实体识别与 formulation generation。

### 3.2 再解决“能否端到端生成并执行 solver code”

Auto Model Generator、OptLLM、OptiMUS 引入编译、执行和错误修复闭环。

### 3.3 再解决“如何提高复杂度、泛化和可靠性”

ORLM 用大规模合成数据训练专用模型；LLMOPT 引入统一五元素表达与自纠错；OptMATH 用 solver/rejection sampling 保证数据质量；Mamo 用 solver 做过程验证；EquivaMap 处理不同 formulation 的功能等价性。

### 3.4 最新问题变成“系统架构能否比单纯堆模型更重要”

【原文事实】OptiMUS-0.3（59）明确指出模块化架构与针对性错误修复是性能主要驱动因素之一，且系统架构的重要性可以超过单纯换更强模型。

## 问题状态

**强前沿但相对独立于本研究 selector 主线**。它提供最重要的方法论：LLM 应和 deterministic solver / verifier / execution feedback 组成闭环，而不是被当作孤立求解器。

---

# 阶段 4｜自动算法设计：从“LLM 给解”转为“LLM 设计 heuristic”

## 代表演进

EoH（69）/ ReEvo（68）
→ HSEvo（45）、QUBE（44）、MCTS-AHD（43）
→ LLaMEA-HPO（53）、EoH-S（18）、MEoH（54）
→ AutoPBO（16）、EvoPlace（30）、AutoRNet（50）等复杂系统设计。

## 为什么出现

直接求解难以扩展，而传统 AHD 又受限于人工定义 primitive。

于是问题改为：

> 不让 LLM 每次解实例，而让它设计一个可重复执行的 heuristic / algorithm，是否更有效？

## 已解决

- EoH 将“thought + code”共同进化；
- ReEvo 用 reflection 产生 verbal gradient；
- 生成 heuristic 可由传统 evaluator 在大量实例上检验；
- 已从单函数扩展到完整算法/solver components。

## 新问题

- search space 巨大；
- evaluation 很贵；
- 容易早熟收敛；
- LLM 调参效率低；
- 单一 heuristic 跨实例/分布泛化不足；
- 单一最终分数无法描述搜索过程和实际成本。

## 问题状态

**A级强前沿，且已进入“第二阶段问题”**：研究焦点不再只是生成，而是搜索机制、反馈质量、效率、组合和泛化。

---

# 阶段 5｜从“生成一个好 heuristic”到“管理 heuristic 搜索过程”

## 触发原因

早期 LLM-AHD 已经证明能生成好 heuristic，因此新的瓶颈变成：

> 如何更有效地搜索 heuristic space？

## 关键分化

- ReEvo（68）：reflection / verbal gradient；
- HSEvo（45）：显式维护 diversity；
- QUBE（44）：quality + uncertainty 平衡探索/利用；
- MCTS-AHD（43）：用 tree search 保留暂时表现差但潜力高的路径；
- Planning of Heuristics（40）：把 heuristic improvement 明确建模成 state-action-reward 的规划过程；
- PathWise（05）：以 stateful search memory / trajectory 进行高层策略决策；
- DASH（07）：关注整个搜索 trajectory、runtime schedule 和 re-adaptation；
- Hercules（26）：预测 heuristic 性能以节约真实 evaluation。

## 问题状态

**正在快速形成的强前沿**。核心变化是：评价对象从“最终 heuristic”升级为“heuristic 如何被发现的过程”。

---

# 阶段 6｜从单 heuristic 到组合、portfolio 与系统级协同

## 触发原因

一个 heuristic 很难覆盖所有实例、阶段和分布。

## 代表证据

- EoH-S（18）：从单 heuristic 转向 complementary heuristic set；
- E2OC（06）：研究多个 operator 的 interdependence 与 co-evolution；
- MEoH（54）/ MPaGE（21）：考虑多目标 trade-off，而不是单一 best score；
- AutoPBO（16）、EvoPlace（30）：从小函数设计扩展到多个 solver component / industrial algorithm structure；
- HeurAgenix（23）：先构建 heuristic pool，再根据当前 state 在线选择。

## 问题转移

从：

> 找到一个最好的 heuristic

转向：

> 如何拥有一组互补策略，并在正确的时刻调用正确的策略？

## 问题状态

**B→A级快速上升方向**，也是与用户当前研究最直接相交的位置。

---

# 阶段 7｜在线上下文决策：LLM 应不应该成为高层 selector？

## 代表证据

### HeurAgenix（23）

【原文事实】它已经明确属于 selection hyper-heuristic：根据当前 problem state，从 heuristic pool 在线选择 heuristic。

### Wireless Power Control（58）

【原文事实】其 in-context decision 使用当前 state，并将历史 `(state, action, reward)` 保存在 experience pool 中供后续决策。

### ReflecSched（19）

【原文事实】在 dynamic FJSP 中，LLM 通过跨 horizon 的反思提炼 strategic experience，再指导即时调度决策。

### MA-GTS（37）

【原文事实】根据图问题约束和规模动态选择算法。

## 重要结论

【分析判断】因此，以下说法已经不能作为创新：

- “第一次让 LLM 根据状态选 heuristic”；
- “第一次让 LLM 使用历史反馈做在线决策”；
- “第一次把 LLM 用于动态调度”。

真正剩余的问题已经被压缩为：

> 在更明确、更可控的优化搜索层级上，LLM 能否利用传统 RL selector 难以统一表达的多源上下文，并在公平预算下产生可验证的增益？

## 问题状态

**新兴且竞争迅速增强。**

---

# 阶段 8｜当前最前沿的问题：动态、可验证、成本受控的混合决策系统

## 【文献归纳】最新问题不是“LLM vs solver”，而是角色分工

越来越多论文开始把系统拆成：

**语义/高层推理层** + **快速执行层** + **反馈/验证层**。

表现为：

- LLM 负责生成/选择/解释；
- solver / EA / local search / simulator 负责执行；
- objective / verifier / solver log / reward / critique 提供反馈；
- memory / trajectory / archive 保存历史；
- 预算、延迟、泛化和 robustness 被纳入评价。

## 当前未稳定解决的能力

1. 如何统一编码环境状态与**搜索过程状态**；
2. 如何利用长期策略效果而非只看即时 reward；
3. 如何在动态事件发生后快速适应，不重新大规模训练；
4. 如何让 LLM 决策成本不吞掉优化收益；
5. 如何在 multi-objective / Pareto search 中定义高层反馈；
6. 如何用严格同预算实验判断“LLM 的语义推理”是否真的比简单 selector 值得。

## 问题状态

**真正的机会窗口层**。

# 最终问题演进链

```text
人工建模 / 人工 heuristic
        ↓
自动配置 / Algorithm Selection / Hyper-Heuristic / AOS
        ↓
学习型 selector（ML / RL / Q-learning）
        ↓
LLM 直接建模 / 直接求解
        ↓
LLM + solver / verifier 的混合系统
        ↓
LLM 生成 heuristic / algorithm（AHD / LHH）
        ↓
reflection / uncertainty / diversity / MCTS / trajectory-aware search
        ↓
单 heuristic → heuristic set / multi-operator / multi-component
        ↓
在线 contextual selection / dynamic decision
        ↓
动态 + 多目标 + 搜索过程感知 + 历史反馈 + 成本受控的高层决策系统
```

# 对当前研究的直接含义

【分析判断】当前课题不能把创新写成“LLM 替代 Q-learning”本身。更稳的研究问题应围绕：

> 在固定 NSGA-II / decoder / 策略库 / 动态事件 / 评价预算的条件下，LLM 是否能把 **动态调度环境状态 + 多目标 Pareto 搜索状态 + 搜索阶段/停滞 + 历史策略效果 + 剩余预算** 统一成 contextual decision，并在对 Q-learning selector 的单模块替换实验中获得更好的泛化、样本效率或最终 Pareto 性能？

这仍是【待验证】研究机会，不是已确认 novelty。
