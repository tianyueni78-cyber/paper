# 24｜技术演进与代表文献树

> 结构：Problem → Method → Decision Layer → Mechanism → Representative Papers。
>
> 目的：维护“技术怎么演进”，而不是维护“论文有哪些”。

# 1｜Automated Optimization

## 1.1 Fixed human-designed optimization

**Problem**：算法/heuristic 主要由人设计。

**Method**：fixed heuristic / handcrafted metaheuristic / solver configuration。

**Decision Layer**：Human design layer。

**Mechanism**：人工指定算法结构、规则、operator、参数。

**Representative foundations**：`78,79`

↓

## 1.2 Algorithm Selection / HH / AOS

**Problem**：一个固定 heuristic 无法适应所有实例/搜索阶段。

**Decision Layer**：High-level selection。

**Mechanism**：features / credit → select from LLH/operator pool → executor。

**Representative Papers**：`78,65`

↓

## 1.3 RL / Q-learning selector

**Problem**：人工 rule / static selection 适应性有限。

**Decision Layer**：Learned selection policy。

**Mechanism**：state → action/heuristic → reward → policy/Q update。

**Current-study comparator**：原 Q-learning HH。

---

# 2｜LLM for Optimization

## 2.1 Direct Solution Generation

**Problem**：能否让 LLM 直接充当 optimizer？

**Decision Layer**：Solution layer。

**Mechanism**：problem + history/reasoning → candidate solution → checker/objective。

**Representative Papers**：`73 OPRO, 63 SGE, 36 STARJOB, 61 GraphArena, 75 NLGraph`

**Boundary**：规模、结构推理、可行性与 hallucination 风险。

↓

## 2.2 LLM Formulation + Classical Solver

**Problem**：LLM 数值/组合执行不稳定，但语义理解和代码生成较强。

**Decision Layer**：Modeling / tool-use layer。

**Mechanism**：NL → formulation/code → solver → error/result → correction。

**Representative Papers**：`77 NL4Opt, 74 Holy Grail 2.0, 60 OptLLM, 67/59 OptiMUS, 76 Auto Model Generator, 64 Mamo, 62 ORLM`

**Key evolution**：从一次生成走向 solver-verified closed loop。

↓

## 2.3 LLM Heuristic Generation / AHD

**Problem**：让 LLM 不直接求每个实例，而是设计可重复执行的算法。

**Decision Layer**：Algorithm / heuristic design layer。

**Mechanism**：task → thought/code heuristic → evaluator → evolutionary/reflection update。

**Representative Papers**：`69 EoH, 68 ReEvo, 03 CVRP-AHD, 25,26`

↓

## 2.4 Search-process-aware AHD

**Problem**：只看 final fitness 浪费搜索过程信息。

**Decision Layer**：Heuristic-design search control。

**Mechanism**：trajectory / uncertainty / diversity / lineage / runtime → next design action。

**Representative Papers**：

- `05 PathWise`：stateful trajectory + memory + world model
- `07 DASH`：trajectory-aware convergence + runtime schedule
- `43 MCTS-AHD`：tree search
- `44 QUBE`：quality-uncertainty trade-off
- `45 HSEvo`：population diversity
- `40 Planning of Heuristics`：heuristic improvement as planning/MDP

↓

## 2.5 Portfolio / Multi-operator / System-level AHD

**Problem**：单一 heuristic 不足以覆盖复杂状态与 trade-off。

**Decision Layer**：Portfolio / operator-system design。

**Mechanism**：co-evolution / complementary set / multiobjective heuristic design / component design。

**Representative Papers**：

- `18 EoH-S`：complementary heuristic set
- `06 E2OC`：interdependent operators + co-evolution
- `21 MPaGE`：Pareto-grid multiobjective design
- `54 MEoH`：non-dominated heuristic set
- `16 AutoPBO, 30 EvoPlace, 50 AutoRNet`：system/component-level design

---

# 3｜LLM Runtime Control

## 3.1 Contextual Heuristic Selection

**Problem**：已有 heuristic pool 后，运行时应该用哪个？

**Decision Layer**：Online high-level selection。

**Mechanism**：current state → LLM selector → heuristic pool → executor。

**Representative Paper**：`23 HeurAgenix`

**Boundary implication**：

> “LLM 从 heuristic pool 在线选择”已不能作为 novelty。

↓

## 3.2 Contextual Algorithm / Action Selection

**Problem**：上下文不只决定 heuristic，也可能决定 algorithm 或动作。

**Decision Layer**：Algorithm/action selection。

**Mechanism**：constraints / scale / environment state / experience → action or algorithm。

**Representative Papers**：

- `37 MA-GTS`：constraints + graph scale → algorithm selection
- `58 Wireless Power Control`：state + experience(state,action,reward) → online action

↓

## 3.3 Dynamic Strategic Control

**Problem**：环境本身持续变化，需要在时间轴上调整决策。

**Decision Layer**：Dynamic supervisory / scheduling decision。

**Mechanism**：dynamic observation → reflection / strategic experience → instantaneous decision。

**Representative Paper**：`19 ReflecSched`

**Boundary implication**：

> “LLM + dynamic FJSP”本身已不足以构成创新。

↓

## 3.4 Slow-fast Hierarchical Control

**Problem**：LLM 适应性强，但高频调用慢且贵。

**Decision Layer**：Low-frequency supervisory design + high-frequency lightweight execution。

**Mechanism**：LLM periodically improves policy/rule → fast online policy executes。

**Representative Paper**：`09 TPET`

**Open question**：什么调用频率、动态强度和收益水平下 online LLM 才值得？

# 4｜Multi-objective / Pareto Evolution

## 4.1 Multi-objective problem optimization

**Problem**：同时优化多个冲突目标。

**Current study**：makespan + TEC。

**Mechanism**：quality / efficiency / diversity / runtime 等形成 Pareto trade-off。

**Representative direct evidence**：当前 69 篇中尚未确认与本研究同构的直接工作。

# 6｜当前研究在树上的位置

```text
Dynamic Multi-objective FJSP-AGV
→ Runtime Adaptive Optimization
→ High-level Strategy Selection
→ Fixed Strategy / Operator Library
→ LLM Contextual Supervisory Selector
→ Environment State + Search-process State + Pareto State + History + Remaining Budget
→ Fixed NSGA-II + Original Decoder executes
→ Makespan / TEC / HV / Real Decode Count / Strategy Effect
→ Feedback to next supervisory decision
```

## 最近邻文献

- selection：`23 HeurAgenix`
- dynamic FJSP：`19 ReflecSched`
- history-aware online decision：`58 Wireless Power Control`
- search-process-aware control：`05,07,43,44,45`
- Pareto design：`21,54`
- slow-fast / latency counter-route：`09 TPET`

## 研究差异必须从这些字段中产生

1. **State composition**：environment + search + Pareto + history + budget 是否联合；
2. **Credit**：即时 reward 还是 trajectory-level realized strategy effect；
3. **Objective representation**：scalar reward 还是 Pareto-aware effect；
4. **Comparator**：是否与 Q-learning/strong rule/AOS 做公平单模块替换；
5. **Cost boundary**：质量增益是否覆盖 latency/token/call cost；
6. **Generalization**：unseen event combination / instance scale 是否需要重训。

如果这些字段没有可复现增益，研究就会退化成“把 Q-learning 换成 LLM”。那不叫创新，最多叫接口改造。
